# RuntimeHost — Interface Design Comparison

Generated by `/design-an-interface`. Four parallel sub-agents, each constrained
to a radically different design philosophy. The point is the contrast.

| Design | Constraint | Method count | In-memory mock LOC | Best fit |
|---|---|---:|---:|---|
| A | Declarative reconciliation (k8s-style) | 2 | ~28 | Cross-adapter parity, k8s-shaped infra |
| B | Full RPC service (gRPC-style) | 14 | ~140 | Hybrid platform composability, ops surface |
| C | Channel-typed handles (no shared base) | 9 (5 + 4) | ~180 | CF-native + Fly, honest physics |
| D | Actor / OTP-style primitives | 7 | ~150 | Cloudflare-only, Erlang-literate teams |

**Recommendation up front:** **C as the spine** + **A's `watch()` async-iterator** + **B's diagnostic methods (`listHosts`, `selfCheck`) on the platform**. **Reject D** for the team profile and platform mix. Reasoning at the bottom in §5.

---

## Design A — Declarative reconciliation (≤ 2 methods)

### 1. Interface signature

```typescript
export type ChannelKind = 'voice' | 'messaging';

export type ComplianceMode = 'none' | 'hipaa' | 'ferpa' | 'tcpa';

export type IsolationKind =
  | 'per-conversation'   // messaging on CF DO (hibernating)
  | 'per-workspace'      // voice on CF Container / Fly Machine
  | 'pooled';            // messaging on Fly/k8s with consistent-hash

export type RuntimePhase =
  | 'Pending'
  | 'Provisioning'
  | 'Ready'
  | 'Draining'
  | 'Terminated'
  | 'Failed';

/**
 * Stable, content-addressed identity. Format:
 * `${channelKind}:${workspaceId}:${conversationScope}` where conversationScope
 * is conversationId for per-conversation, workspaceId for per-workspace, or a
 * hash bucket id for pooled. Adapters compute this.
 */
export type RuntimeKey = string & { readonly __brand: 'RuntimeKey' };

export interface RuntimeSpec {
  readonly workspaceId: string;
  readonly channelKind: ChannelKind;
  readonly conversationId: string;
  readonly region: string;
  readonly complianceMode: ComplianceMode;
  readonly agentVersionId: string;
  /** Monotonic; bumped by caller on field change. */
  readonly generation: number;
}

export interface RuntimeStatus {
  readonly key: RuntimeKey;
  readonly spec: RuntimeSpec;
  readonly observedGeneration: number;
  readonly phase: RuntimePhase;
  readonly isolation: IsolationKind;
  readonly region: string;
  readonly bundleHash: string;
  readonly actorAddress: string | null;
  readonly startedAt: Date | null;
  readonly lastHeartbeatAt: Date | null;
  readonly terminatedAt: Date | null;
  readonly terminationReason: string | null;
  readonly lastError: { message: string; at: Date } | null;
}

export type RuntimeIntent =
  | { kind: 'spec'; spec: RuntimeSpec }
  | { kind: 'retire'; key: RuntimeKey; drain: boolean; reason: string };

export type RuntimeSelector =
  | { kind: 'key'; key: RuntimeKey }
  | { kind: 'workspace'; workspaceId: string; channelKind?: ChannelKind }
  | { kind: 'all' };

export interface RuntimeHost {
  /**
   * Declare desired state. Idempotent on (key, generation). Persists spec;
   * reconciler converges in finite time. Returns immediately — does NOT
   * wait for Ready. To wait, watch().
   */
  apply(intent: RuntimeIntent): Promise<RuntimeKey>;

  /**
   * Subscribe to status. First yield is current snapshot, subsequent yields
   * are change events. At-least-once delivery of phase transitions.
   */
  watch(selector: RuntimeSelector): AsyncIterable<RuntimeStatus>;
}

export interface IsolationPolicy {
  deriveIsolation(input: {
    channelKind: ChannelKind;
    complianceMode: ComplianceMode;
  }): { isolation: IsolationKind; idleTimeoutMs: number };
}
```

### 2. Usage — per-channel routing (the canonical case)

```typescript
async function handleInbound(host: RuntimeHost, evt: InboundChannelEvent) {
  const spec: RuntimeSpec = {
    workspaceId:    evt.workspaceId,
    channelKind:    evt.channelKind,
    conversationId: evt.conversationId,
    region:         evt.region,
    complianceMode: evt.workspace.complianceMode,
    agentVersionId: evt.workspace.activeAgentVersionId,
    generation:     evt.workspace.specGeneration,
  };

  const key = await host.apply({ kind: 'spec', spec });

  for await (const s of host.watch({ kind: 'key', key })) {
    if (s.phase === 'Ready' && s.actorAddress) return forwardToActor(s.actorAddress, evt);
    if (s.phase === 'Failed') return new Response('runtime failed', { status: 503 });
  }
}
```

The Worker has zero `if (channelKind === 'voice')` branches. The CF adapter sees `channelKind: 'voice'` and places on a `WorkspaceVoiceDO`'s Container; sees `channelKind: 'messaging'` and places on a per-conversation hibernating DO.

### 2(d). In-memory mock — 28 lines

```typescript
export class InMemoryRuntimeHost implements RuntimeHost {
  private readonly state = new Map<RuntimeKey, RuntimeStatus>();
  private readonly listeners = new Set<(s: RuntimeStatus) => void>();

  async apply(intent: RuntimeIntent): Promise<RuntimeKey> {
    if (intent.kind === 'retire') {
      const cur = this.state.get(intent.key);
      if (cur) this.emit({ ...cur, phase: 'Terminated', terminatedAt: new Date(),
                          terminationReason: intent.reason });
      return intent.key;
    }
    const key = `${intent.spec.channelKind}:${intent.spec.workspaceId}:${intent.spec.conversationId}` as RuntimeKey;
    this.emit({
      key, spec: intent.spec, observedGeneration: intent.spec.generation,
      phase: 'Ready', isolation: 'per-conversation', region: intent.spec.region,
      bundleHash: 'test', actorAddress: `mem://${key}`,
      startedAt: new Date(), lastHeartbeatAt: new Date(),
      terminatedAt: null, terminationReason: null, lastError: null,
    });
    return key;
  }

  async *watch(sel: RuntimeSelector): AsyncIterable<RuntimeStatus> {
    for (const s of this.state.values()) if (this.match(sel, s)) yield s;
    const queue: RuntimeStatus[] = []; let resolve: (() => void) | null = null;
    this.listeners.add(s => { if (this.match(sel, s)) { queue.push(s); resolve?.(); }});
    while (true) { while (queue.length) yield queue.shift()!;
      await new Promise<void>(r => { resolve = r; }); }
  }

  private emit(s: RuntimeStatus) { this.state.set(s.key, s); this.listeners.forEach(l => l(s)); }
  private match(sel: RuntimeSelector, s: RuntimeStatus): boolean {
    return sel.kind === 'all' || (sel.kind === 'key' && sel.key === s.key) ||
      (sel.kind === 'workspace' && s.spec.workspaceId === sel.workspaceId &&
        (!sel.channelKind || s.spec.channelKind === sel.channelKind));
  }
}
```

### 3. Trade-offs (selected highlights — see full design for all five axes)

- **Cognitive load:** Wins on surface area; loses on indirection. New devs write awkward `for await … if (Ready) break` loops the first few times.
- **Test affordance:** Strong win — 28 lines, no actor mock needed.
- **Failure modes:** `apply()` returns a key before the host is provisioned. Naive code that doesn't check `phase === 'Failed'` hangs on `watch()` forever.
- **Cross-adapter parity:** Strongest argument for this design. `IsolationKind` is the universal vocabulary. `actorAddress: string` is the stringly-typed escape hatch.
- **Composability:** Mixed. Hybrid is straightforward; granular routing forces a wrapper that re-implements selector logic. Imperative use cases ("burst this one call to a different region") fight the design.

## Design B — Full RPC service (14 methods)

### 1. Interface signature


### 2. Usage — per-channel routing

```typescript
async function onTwilioInbound(req: TwilioInboundRequest) {
  const { host: h, transport } = await runtimeHost.acceptIncomingCall({
    workspaceId: req.workspaceId, conversationId: req.conversationId,
    region: req.region, complianceMode: req.complianceMode,
    agentVersionId: req.agentVersionId,
    twilioCallSid: req.callSid, mediaStreamUpgradeUrl: req.wssUpgradeUrl,
  });
  return { redirectTo: h.actorAddress, transport };
}

async function onWhatsAppInbound(req: WhatsAppInboundRequest) {
  const { transport } = await runtimeHost.dispatchMessage({
    workspaceId: req.workspaceId, conversationId: req.conversationId,
    region: req.region, complianceMode: req.complianceMode,
    agentVersionId: req.agentVersionId,
    threadKey: req.from,
    message: { text: req.body, attachments: req.media },
  });
  await transport.send({ kind: 'message', text: req.body, ts: Date.now() });
}
```

### 3. Trade-offs (highlights)

- **Cognitive load:** Heaviest. 14 methods, four of which (placeCall/acceptIncomingCall/openWidgetSession/dispatchMessage) overlap heavily in shape.
- **Test affordance:** ~140-line in-memory mock. Each method is independently mockable — partial mocks are easy.
- **Failure modes:** Method-level granularity helps surface failure types. Cost: caller writes distinct recovery paths for spawn/mid-call/drain.
- **Cross-adapter parity:** Sharpest weakness. `dispatchMessage` is trivial on CF (one DO per conversation), complex on Fly (consistent-hash on pooled service). `rotateBundle` with `hot-swap` is "basically a lie" on a CF DO that owns a Container — adapter will silently downgrade to drain-then-rotate.
- **Composability:** Strongest. Hybrid adapter routes per-method based on input channel intent — straightforward switch statement.

## Design C — Channel-typed handles (two interfaces, no shared base)

### 1. Interface signatures

The voice/messaging split is treated as a fundamental difference in physics. There is no `BaseRuntimeHost`. The discriminator lives in the *factory*; the discrimination lives in the *type system*.

```typescript
// VOICE — per-workspace long-lived host hosts N concurrent calls.
// HOST is acquired ONCE per workspace; SESSIONS attached as children.
export interface VoiceRuntimeHost {
  acquireHost(input: VoiceAcquireInput): Promise<VoiceHostHandle>;
  attachSession(host: VoiceHostHandle, input: VoiceAttachInput):
    Promise<{ session: VoiceSessionHandle; channel: VoiceMediaChannel }>;
  openSupervisorTap(session: VoiceSessionHandle): Promise<VoiceSessionTap>;
  watchHeartbeat(host: VoiceHostHandle): AsyncIterable<VoiceHeartbeat>;
  beginDrain(host: VoiceHostHandle, reason: string): Promise<VoiceDrainPlan>;
}

// MESSAGING — per-conversation hibernating actor.
// EVENTS are dispatched and routed; "host" is an addressing scheme.
export interface MessagingRuntimeHost {
  resolveActor(input: MessagingResolveInput): Promise<MessagingActorRef>;
  dispatch(input: MessagingDispatchInput): Promise<MessagingDispatchResult>;
  openConversationLog(ref: MessagingActorRef): Promise<MessagingConversationLog>;
  inspectHibernation(ref: MessagingActorRef): Promise<MessagingHibernationStatus>;
  evictionPlan(): MessagingEvictionPlan;
}

// THE PLATFORM FACTORY — only place channelKind appears.
export interface RuntimePlatform {
  readonly voice: VoiceRuntimeHost;
  readonly messaging: MessagingRuntimeHost;
}

export function pickHost(platform: RuntimePlatform, channelKind: 'voice'): VoiceRuntimeHost;
export function pickHost(platform: RuntimePlatform, channelKind: 'messaging'): MessagingRuntimeHost;
export function pickHost(p: RuntimePlatform, k: 'voice' | 'messaging') {
  return k === 'voice' ? p.voice : p.messaging;
}
```

(Supporting types: `VoiceHostHandle`, `VoiceSessionHandle`, `VoiceMediaChannel` with `pushInbound`/`outbound`/`pushControl`/`close`, `VoiceSessionTap`, `VoiceHeartbeat`, `VoiceDrainPlan` with three explicit phases, `MessagingActorRef`, `MessagingInbound`/`Outbound` frame types, `MessagingDispatchResult`, `MessagingConversationLog`, `MessagingHibernationStatus`, `MessagingEvictionPlan`.)

### 2. Usage — per-channel routing

```typescript
// Twilio Media Streams → voice
async function onTwilioWssUpgrade(req: Request, ws: WebSocket, ctx: CallContext) {
  const voice = pickHost(platform, 'voice');
  const host = await voice.acquireHost({ workspaceId: ctx.workspaceId, region: ctx.region,
    complianceMode: ctx.complianceMode, agentVersionId: ctx.agentVersionId });
  const { session, channel } = await voice.attachSession(host, {
    conversationId: ctx.callId,
    carrierHandshake: { callSid: ctx.twilioCallSid, accountSid: ctx.twilioAccountSid },
  });
  ws.addEventListener('message', e => channel.pushInbound(new Uint8Array(e.data as ArrayBuffer)));
  for await (const frame of channel.outbound) ws.send(frame);
}

// WhatsApp webhook → messaging
async function onWhatsAppWebhook(req: Request, ctx: WebhookContext) {
  const messaging = pickHost(platform, 'messaging');
  const ref = await messaging.resolveActor({ workspaceId: ctx.workspaceId,
    conversationId: ctx.threadKey, region: ctx.region,
    complianceMode: ctx.complianceMode, agentVersionId: ctx.agentVersionId });
  const result = await messaging.dispatch({ ref,
    event: { kind: 'wa-webhook', payload: await req.json(), receivedAt: new Date() },
  });
  for (const out of result.producedOutbound) await deliverOutbound(out);
  return new Response('ok');
}
```

The two handlers don't share a single line of plumbing past `pickHost`.

### 3. Trade-offs (highlights)

- **Cognitive load:** Net loss for newcomers (two interfaces), net win for working engineers (autocomplete shows only relevant methods, no "does this method apply to my channel kind?" question).
- **Test affordance:** Two `Map`-backed mocks, ~40% more lines than a unified mock. Honest duplication — voice has continuous duplex channels with backpressure; messaging is `Map<ConversationId, History>`.
- **Failure modes:** Strongest debuggability. Channel-typed errors are pre-discriminated at the type level; stack traces are clearer; dashboards are pre-segmented.
- **Cross-adapter parity:** **Voice fits CF and Fly cleanly. Messaging fits CF cleanly, fits Fly awkwardly, fits k8s very awkwardly.** `isolationKind='k8s-deployment-shared'` exposes that the abstraction is leaking — honest, not pretending.
- **Composability:** **Strongest moat.** Hybrid is structurally trivial: `new HybridRuntimePlatform(new CloudflareVoiceHost(env), new FlyMessagingHost(redisUrl))`. Because no shared base, mixing is structurally guaranteed not to break anything.
- **Named flaws:** Forced asymmetry hurts cross-cutting concerns. Postgres `runtime_deployments` row is shared but interfaces pretend it isn't. Adding a third channel (`'video'`, `'rcs'`) means a third interface AND auditing every dispatch.

## Design D — Actor / OTP-style primitives (7 methods)

### 1. Interface signature

```typescript
export type Pid = {
  readonly __pid: unique symbol;
  readonly node: string;       // "cf:do:<id>", "fly:machine:<id>", "k8s:pod:<name>"
  readonly id: string;
};

export type ActorName =
  | { kind: 'workspace-voice'; workspaceId: string }
  | { kind: 'conversation-messaging'; workspaceId: string; conversationId: string }
  | { kind: 'system:registry' }
  | { kind: 'system:supervisor' }
  | { kind: 'system:deployments' };

export type Spec = {
  readonly behavior: 'workspace-voice' | 'conversation-messaging';
  readonly workspaceId: string;
  readonly conversationId?: string;
  readonly region: string;
  readonly complianceMode: 'none' | 'hipaa' | 'ferpa' | 'tcpa';
  readonly agentVersionId: string;
  readonly bundleHash: string;
  readonly restart: 'one_for_one' | 'transient' | 'temporary';
  readonly idleTimeoutMs: number;
};

export type HostMsg =
  | { tag: 'attach-inbound'; conversationId: string;
      transport: { kind: 'twilio-ws'; upgrade: Request } | { kind: 'whatsapp-webhook'; payload: unknown } | { kind: 'browser-widget'; socket: WebSocket };
      replyTo: Pid }
  | { tag: 'subscribe-tap'; conversationId: string; subscriber: Pid }
  | { tag: 'unsubscribe-tap'; conversationId: string; subscriber: Pid }
  | { tag: 'drain'; deadlineMs: number; reason: string }
  | { tag: 'heartbeat-poke' };

export type HostCall =
  | { tag: 'health' }
  | { tag: 'session-state'; conversationId: string }
  | { tag: 'list-sessions' };

export type ExitReason =
  | { kind: 'normal' }
  | { kind: 'shutdown'; reason: string }
  | { kind: 'killed' }
  | { kind: 'crash'; error: unknown }
  | { kind: 'noproc' }
  | { kind: 'platform'; detail:
      | { adapter: 'cf'; subKind: 'do-evicted' | 'container-oom' | 'cpu-budget' }
      | { adapter: 'fly'; subKind: 'machine-restarted' | 'host-drained' | 'oom' }
      | { adapter: 'k8s'; subKind: 'pod-evicted' | 'oom-killed' | 'preempted' } };

export interface ActorSystem {
  spawn(spec: Spec): Promise<Pid>;
  cast(target: Pid | ActorName, msg: HostMsg): void;
  call(target: Pid | ActorName, msg: HostCall, timeoutMs: number): Promise<HostCallReply>;
  link(a: Pid, b: Pid): void;
  unlink(a: Pid, b: Pid): void;
  monitor(target: Pid, observer: Pid): string /* monitorRef */;
  demonitor(monitorRef: string): void;
  exit(target: Pid, reason: ExitReason): void;
  whereis(name: ActorName): Promise<Pid | null>;
  self(): Pid;
}
```

System actors: `system:registry`, `system:deployments` (owns `runtime_deployments` writes), `system:supervisor` (clamps HIPAA → idleTimeoutMs ≤ 30s).

### 2. Usage

```typescript
async function ensureVoiceWorkspace(ctx: InboundCtx): Promise<Pid> {
  const name = { kind: 'workspace-voice', workspaceId: ctx.workspaceId } as const;
  const existing = await system.whereis(name);
  if (existing) return existing;
  return system.spawn({
    behavior: 'workspace-voice',
    workspaceId: ctx.workspaceId, region: ctx.region,
    complianceMode: ctx.complianceMode, agentVersionId: ctx.agentVersionId,
    bundleHash: ctx.bundleHash,
    restart: ctx.complianceMode === 'hipaa' ? 'transient' : 'one_for_one',
    idleTimeoutMs: ctx.complianceMode === 'hipaa' ? 30_000 : 5 * 60_000,
  });
}

export async function onTwilioUpgrade(req: Request, ctx: InboundCtx) {
  const pid = await ensureVoiceWorkspace(ctx);
  const reply = await system.call(pid, { tag: 'health' }, 2_000);
  if (reply.tag !== 'health' || reply.state === 'dead') return new Response('upstream', {status: 502});
  system.cast(pid, { tag: 'attach-inbound', conversationId: ctx.conversationId,
    transport: { kind: 'twilio-ws', upgrade: req }, replyTo: system.self() });
  return new Response(null, { status: 101 });
}
```

### 3. Trade-offs (highlights)

- **Cognitive load:** **Single biggest cost.** Most TS engineers don't have OTP intuition. Onboarding requires written primer, months of code review. Erlangists love it; median TS engineer finds it alien.
- **Test affordance:** ~150-line harness. Once it exists, tests express scenarios in their natural shape ("spawn, monitor, assert DOWN with reason=…").
- **Failure modes:** Strength — DOWN is the single concept across platforms. Leak — `ExitReason.platform` is a confession that CF/Fly/k8s have different recovery semantics.
- **Cross-adapter parity:** **Deepest problem.** "CF DOs are kinda actor-shaped, Fly Machines are not, k8s pods are not." On Fly, "messaging actor for one conversation" is a routing key in a pooled Bun service; spawning that actor doesn't spawn a process. `link` between two such actors is a fiction maintained in Redis. **CF is a real actor system; Fly + k8s wear the costume.**
- **Composability:** Elegant in marketing, not in production. Federation across actor systems would require cross-system message bus, distributed monitor refs — beyond the interface.

## Comparison

### Cognitive load

A wins on surface area (2 methods). C wins on "what working engineers see day to day" (autocomplete is channel-scoped). B is heaviest because of method count overlap (4 spawn methods that look almost identical). D is in a different category — the OTP mental model is a multi-week onboarding tax that wouldn't be paid by the existing team.

### Test affordance

A is the runaway winner: 28 lines, no actor mock, no schedulers. C is honest about duplication (~180 lines across two mocks). B at 140 lines per method-count is reasonable but every method needs a coherent stub. D's 150-line scheduler-and-link harness is the most expensive AND the most error-prone (faking `link` symmetry and `monitor` semantics is where bugs hide).

### Failure modes

The four designs surface failures in fundamentally different shapes:
- **A**: heartbeat-timeout detection in one mechanism, automatic re-convergence. Caller must check `phase === 'Failed'` or hangs forever.
- **B**: 14 distinct rejection sites, each with subtly different state implications. Granular but the contract between methods isn't typed.
- **C**: pre-discriminated by channel — voice errors and messaging errors are different types. Clearest debuggability.
- **D**: uniform DOWN protocol but `ExitReason.platform` is a leak. Forces uniform handling that hides operationally important distinctions.

C wins on debuggability; A wins on simplicity of the recovery loop.

### Cross-adapter parity

This is the most architecturally consequential axis.

- **A** is honest about the parity through `IsolationKind` as a universal vocabulary, but the `actorAddress: string` is a stringly-typed escape hatch that the channel layer must parse per-platform.
- **B** has the worst parity story — `rotateBundle(hot-swap)` is a "lie" on CF DO+Container, `dispatchMessage` is one line on CF and a hash-ring lookup on Fly. The interface is uniform; the implementations are radically asymmetric.
- **C** explicitly admits voice fits CF/Fly cleanly, messaging fits CF cleanly and Fly/k8s awkwardly. `isolationKind='k8s-deployment-shared'` is honest about the leak.
- **D** has the deepest problem: actor semantics are real on CF DOs, fictional on Fly/k8s. Forcing them produces operationally-misleading abstractions.

C is the most honest. A is the most uniform. B and D both pretend to uniformity that doesn't hold.

### Composability (hybrid platform)

- **A**: dispatch-on-spec works but anything granular requires re-implementing selector logic.
- **B**: easiest hybrid — switch statement per method based on input channel.
- **C**: structurally trivial — `new HybridRuntimePlatform(cfVoice, flyMessaging)` with no shared base means no invariants to violate.
- **D**: federation across actor systems is theoretical; in practice you'd write a service mesh.

C wins decisively here; B is acceptable; A and D both struggle.

## Synthesis — what to ship

**Take C as the spine.** The voice/messaging dichotomy is a real difference in physics, the type system should enforce it, and the hybrid composability is the strongest property of any of the four designs. The "no shared base" decision matches what we already know about Kuralle's actual workload — voice is a long-lived dedicated process, messaging is a hibernating actor — and C is the only design that doesn't pretend they're the same thing.

**Bolt on A's `watch()` async iterator** to each channel interface. C's `watchHeartbeat()` is voice-only, and there's no equivalent on the messaging side. Replacing both with a shared `watch(selector): AsyncIterable<Status>` pattern (parameterized by channel-specific status type) gives us:
- Editor screens that show "is this workspace's voice host ready?" with a single iterator
- Supervisor screens that subscribe to status streams without polling
- Test code that drives status transitions synchronously

**Add a `RuntimePlatformDiagnostics` interface** with `listHosts(filter)`, `selfCheck()`, and `rehydrateHost(hostId)` — borrowed from B. These are real ops needs (the F3 supervisor screen, the admin "list deployments" view, the post-restart actor re-resolution) that C's two-interface split makes awkward. Expose them at the `RuntimePlatform` level, not on the channel interfaces.

**Reject D entirely.** Three reasons:
1. The team's TypeScript-first culture means OTP semantics will not be internalized cheaply.
2. CF DOs are kinda-actor-shaped; Fly Machines and k8s pods are not. Forcing actor semantics on the latter two introduces fictions that break under stress.
3. The composability promise is theoretical — federation across actor systems is a separate large engineering project.

**Borrow D's one good idea — `ExitReason.platform` discriminator.** When something dies, the abstraction needs to expose which platform the failure originated on so incident response can be platform-aware. Add a similarly-shaped `RuntimeFailure` discriminated union to the synthesized interface. Don't pretend platforms are uniform when they aren't.
