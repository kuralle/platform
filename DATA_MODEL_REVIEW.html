0 · Architecture context the critique assumes

If any of these are wrong the gap analysis shifts — flag them.

CTX·1

Transport mix: ~95 % plain WebSocket, ~5 % WebRTC (LiveKit / Daily), small slice of SIP-direct (UDP)

This is the single most load-bearing assumption. It’s why the schema must keep workerId + heartbeat + a router-tier story alive — even though we briefly considered the room-only Pipecat shape (which assumes the opposite mix).

CTX·2

Deploy target split by transport

TransportHostRouting key
Browser WS / Twilio Media Streams / custom WSCloudflare Durable ObjectDO id (= conversation id)
SIP direct (UDP) / SIP-via-WS bridgeFly machine (per call, auto_destroy)workerId + WS router tier
LiveKit / Daily room (5 %)Fly machine joins room as participantroomName via webhook
Chat-only (text)Plain HTTP — no room, no machine spawnconversationId
CTX·3

AriaFlow primitives in scope

Agent, FlowAgent, FlowConfig, SessionStore, onSessionEnd hook, streamCallback sinks, MemoryService for long-term memory. CompositeAgent deliberately not relied upon (no e2e example in aria yet).

1 · P0 blockers

Production correctness or money. Once you ship data, each becomes a backfill + behaviour-change problem at the same time.

P0·1

conversations.workerId + workerKind + heartbeat are missing

BLUEPRINT §9 calls out workerId as a needed addition; DATA_MODEL §8 doesn’t have it. Without this column the Fly+WS path can’t enforce single-owner mutex; the WS router tier can’t locate the right machine; the sweep job can’t finalise calls when a machine dies.

Required even though the CF DO path (95 %) doesn’t strictly need it — schema must support all three transports uniformly.

conversations {
  workerKind         enum('cf-do', 'fly-machine', 'livekit-room')  not null
  workerId           text                  -- DO id | Fly machine id | room name
  workerHostInternal text                  -- fly-only: .internal hostname
  workerSpawnedAt    timestamp
  workerHeartbeatAt  timestamp             -- fly-only: liveness check
}
indexes: ...,
         (workerKind, workerHeartbeatAt) where workerKind = 'fly-machine'
                                           and endedAt is null
P0·2

conversation_turns.intervenedByUserId is missing

BLUEPRINT §9 schema-addition list, not yet in DATA_MODEL. Without it, the audit trail can’t distinguish “agent said X” from “F3 supervisor injected X.” That’s a HIPAA/FERPA-grade audit gap.

conversation_turns {
  intervenedByUserId text references users(id)
}
P0·3

No conversations.status enum (only endedAt IS NULL)

ElevenLabs splits five states: initiated | in-progress | processing | done | failed. The processing state matters because post-call jobs (summary, eval, extraction) run async — F2 must render partial data with a banner instead of pretending it’s complete.

P0·4

No terminationReason on conversations

outcome is business-level (booked / qualified / missed); terminationReason is technical (caller_hangup / agent_hangup / transferred / agent_error / max_duration / network_drop / server_error / worker_died). Two distinct fields. Without the technical one, every triage degenerates into log-grep.

P0·5

Money columns use real (float)

usage_events.unitCostUsd, totalCostUsd, monthly_receipts.recoveredRevenueUsd etc. are real. Floating-point for money drifts under summation. Use numeric(12,6). Also add currency text default 'USD' on usage_events / monthly_receipts / billing_subscriptions for the EU/UK customer that arrives sooner than expected.

P0·6

No optimistic lock on agents / workflows

Two operators editing the same agent silently overwrite each other on save. The agent_revisions table becomes corruption forensics, not an audit trail.

agents     { ..., version integer not null default 0 }
workflows  { ..., version integer not null default 0 }
-- save: UPDATE ... SET ..., version = version + 1
--       WHERE id = $1 AND version = $expected
--       RETURNING version
P0·7

No per-turn latency, TTFB, or interruption flag

conversation_turns has timestampSec but no latencyMs (end-of-user-utterance → start-of-agent-utterance), no firstByteMs, no interrupted / bargeIn flag. These are the voice-UX metrics — without them you can’t compute the latency dashboard customers will demand on day one.

conversation_turns {
  latencyMs    integer       -- user-end → agent-start
  firstByteMs  integer       -- user-end → first audio out
  interrupted  boolean default false
  bargeIn      boolean default false
}

2 · P1 majors

Documented features the schema can’t back. Additive — fold over the next two sprints.

P1·1

No summary / callSummaryTitle on conversations

BLUEPRINT §9 says “add summary text”; DATA_MODEL §8 hasn’t adopted. ElevenLabs ships both transcript_summary + call_summary_title — populated by a post-call worker via onSessionEnd.

P1·2

No search columns for text-search or smart-search

BLUEPRINT §8 references gin(text_tsv); the column itself isn’t on conversation_turns. No summary_embedding vector(1536) on conversations for semantic search. ElevenLabs has both endpoints — the workers can’t populate columns that don’t exist.

P1·3

conversation_extracted_fields has no workflowNodeId

Two extraction nodes both collecting name (intake.name, confirm.name) collide on the (conversationId, label) primary key. Add workflowNodeId to the PK or as a discriminator.

P1·4

Missing denorms: mainLanguage, messageCount, audio metadata

Every list query has to count turns. ElevenLabs returns these inline. Cheap to add; expensive to retrofit through paginated SELECTs. Consider also hasUserAudio / hasResponseAudio for BIPA-style gating (record one side only).

P1·5

No conversationInitiationData jsonb

The snapshot of dynamic vars + overrides + caller metadata used at call start. Without it a flaky call is unreproducible — you can’t even tell which override was active. ElevenLabs persists this; we should too.

P1·6

No workflow_revisions

What happens if a customer edits a workflow during a live call? The running session walks a different graph mid-conversation. Either snapshot workflow into agent_revisions.snapshot (current path — document it explicitly) or add a separate workflow_revisions table with runtime_sessions.workflowRevisionId.

P1·7

workflow_nodes is missing several aria fields

  • inputSchema / outputSchema — required for guard checks (aria FlowNodeConfig 117-119)
  • toolHints — required for voice-mode prompt assembly (aria FlowToolHint 38)
  • llmOverride: text can’t represent aria’s model: LanguageModel | (ctx) => LanguageModel — bump to jsonb
P1·8

No edge priority / ordering on workflow_edges

When multiple edges fire from the same source, which wins? Aria has order; the schema does not. Two conditionType: none edges = race condition.

P1·9

No consent_records table (TCPA)

TCPA requires recording how consent was obtained per phone number — web form timestamp, recorded verbal, signed contract. Not just an opaque DNC bool. Without this, workspace_compliance_posture.tcpa is theatre.

consent_records {
  workspaceId text, phoneE164 text,
  source enum('web_form','verbal_recording','contract','manual'),
  evidenceUrl text, capturedAt, expiresAt
}
P1·10

No DNC list table

batch_recipients.status uses the value dnc, but there’s no table for the workspace DNC list + carrier-merged global DNC. Plus per-call DNC checks need a sub-100 ms lookup, so this needs an indexed table.

P1·11

No eval_scenarios definition table

conversation_evals.scenarioId is text — there’s no place to define what scenarios are. ElevenLabs has tests-create / get / list / delete. The configuration side of evals is a real schema surface, not just stored verdicts.

P1·12

webhooks.events text[] has no event registry

Customers will subscribe to typos. Define a webhook_event_kinds seed table or PG enum and validate on insert.

P1·13

No webhook retry / DLQ policy

webhook_deliveries.attemptCount exists; missing: nextAttemptAt, exponential-backoff config, permanent-failure flag, replay UI. Production webhooks always need a dead-letter queue.

P1·14

No webhook signing rotation grace

signingSecret exists; needs previousSigningSecret + rotatedAt. Accept either signature for ~24 h after rotate; otherwise rotation = brief outage on every customer’s receiver.

P1·15

No usage_events.provider attribution

kind is llm_input_tokens but doesn’t say openai vs anthropic vs google. Cost-per-provider analytics, capacity planning, and contract negotiation all need this. Single column, big payoff.

P1·16

Add conversations.transportKind enum (post-discussion amendment)

The WS / SIP / LiveKit fork forces the schema to know per-call how the call connected — for routing, latency analytics, and eval scoping.

conversations {
  transportKind enum('twilio-media-streams',
                     'twilio-livekit-bridge',
                     'sip-direct',
                     'sip-livekit-bridge',
                     'browser-ws',
                     'widget-ws',
                     'livekit-room',
                     'chat-http')   not null
}

3 · P2 operability gaps

Defer one sprint, not three. Track them so they don’t get lost.

P2·1

Multi-region enforcement is undefined

workspaces.region is set but no DB-level enforcement. Decide: physical sharding (one DB per region) or RLS that joins to workspaces.region on every query. Otherwise an EU customer’s data leaks via a missed app-side filter.

P2·2

No data_subject_requests table (GDPR)

Articles 15-22 (access / rectification / erasure / portability) need a tracked compliance posture. MVP can email; the table is the audit story.

P2·3

kb_documents visibility

Implicit “any workspace member can attach any doc” is fine for SMB, broken for enterprise. Add visibility enum('workspace','admins-only').

P2·4

KB document revisions / dedup

Add kb_documents.contentHash for dedup + change detection. Add kb_chunks.documentRevisionId so re-index doesn’t mid-call mix versions of the same doc.

P2·5

conversation_topics normalised

topics text[] is fine for storage but topics should be normalised entities (id, label, taxonomy parent). ElevenLabs has conv-topics-get.

P2·6

conversation_events stream table

Separate from turns — structured HarnessStreamPart log for analytics replay (matches ElevenLabs events-client / events-server). Defer table; keep event types stable so future migration is additive.

P2·7

agents.canHandoffTo: text[] referential integrity

Same dangling-reference problem as agents.toolIds[] (open question #6 in the source doc). Tombstone-on-delete pattern or normalise to agent_handoffs.

P2·8

runtime_sessions concurrency

Cross-region resume race exists. Add version + UPDATE-WHERE-version pattern, or rely on the workerId mutex for both ownership and resume.

P2·9

Worker sweep job specification

Document the cron explicitly: 30 s tick, scoped to workerKind = 'fly-machine', marks abandoned conversations as terminationReason = 'worker_died', fires onSessionEnd hooks. Without this, dead-Fly-machine calls never finalise.

4 · P3 polish

Genuinely deferrable. Track in open-questions, not in next migration.

P3·1

voice_clones state machine

Current voices.isCloned: boolean can’t express uploading / training / ready / failed. Either separate table or extend the row.

P3·2

agent_groups / folders

At 50+ agents the C1 list breaks UX.

P3·3

notifications inbox

Batch finished, daily digest, compliance flip. Need somewhere to land.

P3·4

feature_flags

For in-product rollouts. Defer until you have a feature worth gating.

P3·5

analytics_dashboards saved views

Saved filter sets, custom date ranges. ElevenLabs has workspace-dashboard-get/update. Customer asks; not strategic.

5 · Cross-cutting smells

Not specific to any column — patterns to fix together.

X·1

BLUEPRINT and DATA_MODEL disagree

BLUEPRINT §9 lists workerId, summary, intervenedByUserId as “schema additions”; DATA_MODEL §8 / §5 don’t have them. Two source-of-truth docs is one source-of-truth doc + a backlog. Fold §9 into the schema doc.

X·2

Aria primitive map (§16) hides assumptions

  • Hooks: code-only — but onSessionEnd drives summary/eval/extraction workers. Without a hook_runs table, debugging post-call failures is grep-the-logs.
  • EvalRunner → conversation_evals — but the definition side is missing (see P1·11).
  • MemoryService → runtime_sessions.workingMemory — that’s session memory. Long-term semantic memory across sessions (the actual MemoryService purpose in aria) has no home.
X·3

JSON-shape opacity

Several jsonb columns ship without a documented schema: secrets.config, tools.config (kind-dependent shape), telephony_connectors.credentials+config. Commit a Zod schema alongside the migration so validation lives with the data, not in app code that drifts.

X·4

text[] over junctions — pick a side

The doc deliberately picks arrays for read simplicity. Real cost on agents.toolIds[] and agents.canHandoffTo[]: dangling references on delete. Either commit to a tombstone-on-delete pattern across the board (and document the cleanup procedure), or normalise those two specifically.

6 · Amendments after the WS / DO / Pipecat thread

Walk-backs and refinements based on the live discussion.

A·1

Confirmed: workerId stays — but as a workerKind + nullable column

The room-only Pipecat shape (which I briefly suggested) doesn’t generalise to your 95 % WebSocket traffic. Schema must support all three transports uniformly, with the column nullable on the CF DO path and required on the Fly path. See P0·1.

A·2

Add transportKind on conversations

New P1·16. Drives routing logic at call start, slices analytics, scopes evals. Derived from phone_numbers.transportKind or widgets.transportKind at insert time.

A·3

Walk back: rooms do not eliminate workerId

I overgeneralised in the Pipecat reply. Rooms simplify the 5 % they apply to. The 95 % still needs the column.

A·4

SIP path: workerHostInternal nullable

SIP/UDP signaling negotiates RTP ports inline. The workerHostInternal column is for WS-on-Fly only; null for SIP-direct on Fly (no proxy hop), and null for CF DO and LiveKit room kinds.
