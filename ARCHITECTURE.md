# Kuralle · Architecture

This document explains how the front-end is wired. Read it once before you start adding screens.

The product name is **Kuralle**. The internal design language is **Vokari** — the
operator-grade aesthetic codified in `.stitch/DESIGN.md`. CSS tokens carry the
`--vokari-*` prefix; user-visible chrome (titles, wordmarks, descriptions) says
Kuralle.

---

## Repo layout

```
kuralle/
├── apps/
│   ├── web/           ← React + TanStack Router app (this is what we ship)
│   └── server/        ← Hono / oRPC server (NOT integrated yet)
├── packages/
│   ├── ui/            ← @kuralle/ui — shadcn primitives + Vokari primitives
│   ├── api/           ← oRPC routers (NOT integrated)
│   ├── auth/          ← Better-Auth (NOT integrated)
│   ├── db/            ← Drizzle schema (NOT integrated)
│   ├── env/           ← shared env shim
│   └── config/        ← shared tsconfigs
└── screens/           ← raw Stitch HTML exports + COMPONENT-MAP.md
```

The current build is **UI + interactivity only**. There is no real auth, no real
API, no DB. All data comes from `apps/web/src/mocks/`. Wire integrations in by
swapping the mock factories with oRPC clients.

## Design tokens

`packages/ui/src/styles/globals.css` is the single source of truth for colour
tokens. Three layers:

1. **Vokari named tokens** — `--vokari-signal-teal`, `--vokari-receipt-gold`,
   etc. — direct hex values from `.stitch/DESIGN.md`.
2. **shadcn semantic aliases** — `--background`, `--primary`, `--foreground`,
   etc. — mapped from Vokari tokens.
3. **Tailwind v4 `@theme inline` block** — exposes both as utility classes
   (`bg-signal-teal`, `text-receipt-gold`).

Three theme scopes:

- **light** (default · the operator workday) — Hush Mist canvas, Signal Teal
  brand.
- **dark** — togglable via `next-themes`. Uses Mission Black tokens.
- **`[data-mode="mission-control"]`** — applied only on the F3 live-supervisor
  route. Forces Mission Black tokens regardless of theme.

Strict colour rules (from DESIGN.md, enforced by code review):

- **Signal Teal** is primary action only — one teal element per viewport.
- **Live Cyan** is reserved for streaming UI — `LiveDot`, live KPI tiles,
  live-row indicators in tables. Never used statically.
- **Receipt Gold** is currency only. Every `$` value flows through `formatUsd()`
  and renders with `text-receipt-gold`.
- **Mission Black** is only for the F3 live-supervisor scope.

## State

- **Workspace context** (`apps/web/src/contexts/workspace.tsx`) — the workspace
  vertical preset, environment, region. Persisted to `localStorage` so reloads
  are sticky. Read from `useWorkspace()` anywhere in the tree.
- **URL state** — F1 conversations list filters live in URL search params
  (TanStack `validateSearch` with Zod). The filter rail mutates them; reloads
  preserve the filter.
- **Component state** — sliders, toggles, transcript playhead live in `useState`
  inside the route component. The F2 transcript turn ↔ waveform player share
  the playhead via a single `position` state hoisted to the route.
- **No Redux, no Zustand, no real cache.** When integrations land, swap the
  mock factories for oRPC clients via `@tanstack/react-query`.

## Mocks

Every screen is backed by `apps/web/src/mocks/`:

```
mocks/
├── seed.ts          ← deterministic PRNG, sparkline generator
├── agents.ts        ← makeAgents(count, vertical?) → Agent[]
├── conversations.ts ← makeConversations(count) → Conversation[]
├── batches.ts       ← makeBatches(count) → Batch[]
├── numbers.ts       ← makePhoneNumbers(count) → PhoneNumber[]
├── kpis.ts          ← makeDashboardKpis(), makeRoiReceipt(month)
└── index.ts         ← re-exports all factories
```

Every factory is **deterministic** — same seed, same output. This makes every
agent-browser snapshot stable, and our tests don't flake.

## Tests

`vitest` + `@testing-library/react` + `jsdom`. `bun run test` from `apps/web`.

```
src/test/
├── setup.ts             ← jsdom polyfills (matchMedia, ResizeObserver)
├── mocks.test.ts        ← deterministic factory contracts
├── format.test.ts       ← formatUsd / formatPct / formatDuration / formatRelative
├── primitives.test.tsx  ← LiveDot, StatusPill, ScopeChip, ComplianceChip,

│                          StickySaveBar, WizardShell
└── workspace.test.tsx   ← WorkspaceProvider, vertical persist, label table
```

34 tests. Run them before pushing — they cover both the cross-screen
primitives and the data layer.

## Verification

After any non-trivial change, snapshot every route via `agent-browser`:

```bash
bun -F web dev:bare &  # boot vite at :3001
agent-browser open http://localhost:3001/<route> --json
agent-browser snapshot --json
agent-browser errors --json | jq '.data.errors | length'
```

## Adding a new screen

1. Create the route file under `apps/web/src/routes/_app.<name>.tsx`.
2. Use `PageHeader` for Tier-1 browse pages, `WizardShell` for wizards.
3. Pull mocks from `@/mocks` rather than fetching anything.
4. Add a `LeftRail` entry in `apps/web/src/components/shell/leftrail.tsx` if
   the screen is reachable from primary nav.
5. Add a `CommandPalette` entry in `apps/web/src/components/shell/command-palette.tsx`
   so ⌘K finds it.
6. Snapshot via `agent-browser` and confirm zero console errors.
7. If you added new shared logic, put a unit test under `src/test/`.
